# Milestone close — the motion

Run from Step 6b after the user confirms the close. Steps in this order; a checkpoint can be interrupted between two of them, and this order leaves nothing dangling.

1. **Graduate durable rules into `knowledge/` — the last time the question can be asked.** After step 3 nothing reads this folder for rules again. Read the retiring milestone's spec `references/` and any accrued emergent rules **in full** and account for **every** rule one of three ways: it graduates; it has a code home that enforces it (name the file); or it died with the milestone. Triage first: a single-code-home value (constant, enum) stays in code; an invariant one test or constraint could enforce → prefer writing that; only a genuinely homeless cross-cutting invariant graduates, written as invariant + why + pointer to the enforcing code. Reconcile against existing knowledge docs (retire or supersede contradicted ones). **Surface the graduate + retire set for the user's confirmation; never curate silently.** Then say: "graduated N rules into `knowledge/` — run `/scaffold-audit` to verify them against the code."
2. **Resolve `## Deferred`.** For each remaining item: confirm shipped (remove), promote (surface for `scaffold-plan` to re-home into the next milestone's `## Deferred` or `roadmap.md` `## Backlog`), or drop with the user's nod. Nothing retires unhandled.
3. **Archive the folder — move it whole, rename nothing.** Check the destination does not already exist, then `git mv .scaffold/milestones/NN-slug .scaffold/milestones/archived/NN-slug` (create `archived/` if absent; plain `mv` only outside git — it nests silently onto an existing directory, so check first). Stamp **`milestone.md` only** with one frontmatter key below `updated:`: `archived: YYYY-MM-DD`. Spec and plans move untouched. Everything under `archived/` is now read-only.
4. **Flip the roadmap line** to `[done]` and repoint its path at `milestones/archived/NN-slug/`.
5. **Repoint `state.md` `## Next`** — it points into the folder you just moved, and it must never resolve inside `archived/`. Aim it at the next milestone, or write that no phase is active and `/scaffold-plan` is the next move. Do this here, not in Step 7: the sweep's mechanical repair for a dangling path is to follow the file, which is the wrong answer for this one.
6. **Report the move — old path and new path** — in the close output and again in the Step 8 review, so the user can grep their own repo for references outside `.scaffold/` (a `CLAUDE.md`, a README, a code comment) that scaffold does not sweep.
7. A pointer'd or external spec is **not cracked open** — only its enduring rules graduate (step 1). The pointer file moves with the folder; the external document it points at is untouched and keeps its own lifecycle.

## Reopening a closed milestone (the user's call, never yours)

The steps run backwards: `git mv` the folder back to `.scaffold/milestones/NN-slug/`, delete the `archived:` key from its `milestone.md`, flip the roadmap line to `[active]` and repoint its path, set `## Next`. Offer it whenever the alternative is a duplicate milestone with a copied spec. Never reopen on your own judgment, and never edit inside `archived/` instead — nothing in the system checks the archive.
